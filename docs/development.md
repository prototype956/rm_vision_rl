# 当前状态与开发顺序

更新：2026-09-10。本文记录当前功能和下一步交付，不保存历史批次清单。

## 已有能力

- 无渲染物理进程、显式步进、重置、暂停查询和多实例通信。
- 出生随机化，静止、正弦平移和匀速旋转目标。
- 请求、供弹、出膛、伤害和弹丸终结事件，以及关窗后自然结算。
- 合成二维测量接入真实 PnP、预测器、弹道和 TinyMPC。
- 禁射预热、规则评估、九动作/只开火回调、观测历史和独立计分。

这些能力支撑脚本策略实验，当前没有 Gymnasium、PPO 训练入口、模型导出或部署模块。历史验收与诊断工具已删除，过去不同版本的报告不作为当前代码的验收结论。

## 阶段二完成标准

阶段二交付可供强化学习算法直接采样的环境，按以下顺序实现：

1. **标准接口。** 定义 observation_space/action_space，提供 Gymnasium reset/step，接通同步回调，明确初始观测和动作生效周期。
2. **奖励和回合边界。** 返回逐步伤害奖励，定义死亡、时间截断、预热超时及异常；明确在途弹丸、尾部结算和价值自举，防止漏算或重复。
3. **所有控制状态的采样。** 无目标或无回调时仍定义观测、动作和时间推进；固定数组类型与掩码，补齐目标重建的历史处理。
4. **多环境适配。** 在独立进程上接入训练器采样，处理终止观测、复位与退出；测量步数/秒及 Reset 耗时，再决定是否优化资产重建或通信。
5. **最小学习验收。** 在己方固定的简单场景跑短训练，证明采样、参数更新、保存和重新加载可用；不要求此时超过传统火控。

检查围绕上述功能，保留时序、奖励、复位、真值隔离和真实闭环的代表性用例。不要为了恢复目录重新生成全部历史专项，也不要把所有矩阵设为日常前置条件。

## 当前问题

| 问题 | 影响 |
| --- | --- |
| 配置工具导入已删除的测试模块 | 生成命令不可用，默认配置下运行库不受影响 |
| Reset 重建物理世界和资产实例 | 采样吞吐仍需测量 |
| 合成测量使用近似噪声、延迟和遮挡 | 不能直接外推完整视觉链路性能 |
| 随机出生可能预热超时 | 需保留并分类处理，不能静默过滤失败样本 |
| 默认 MPC 与 200 次候选配置不同 | 每次明确选择并记录，候选文件不会自动加载 |
| 己方固定、目标仅支持分开的平移/旋转 | 首版明确限制，组合运动和己方移动后续扩展 |

## 后续阶段

基础环境完成后，再扩展场景、对比渲染观测并标定误差，进行只开火与联合换板策略对照。训练器与采样环境优先位于同一台服务器，NUC 承担本地联调和评估。

DGX Spark 是 ARM64，需要单独验证 Rust、C++ 和 Python 依赖。当前工具查询本机 rustc 的动态库目录，尚无独立分发包。模型导出、NUC C++ 推理和实机通信随后实现，不作为基础训练接口完成的前置条件。
