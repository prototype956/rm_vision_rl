## 2. 任务边界

### 2.1 首版范围

- 己方平台为 **17 mm 步兵**。
- 目标覆盖四装甲车辆，包括英雄；按用户确认的新规则，**英雄也使用小装甲板，首版目标均按小装甲建模**。候选是同一已跟踪目标的四个槽位，英雄的车体半径、装甲倾角等仍按其目标模型分别描述。

- 策略使用小型 MLP 与固定短历史，以 **100 Hz / 10 ms** 决策。历史长度和网络具体规模尚待验证。

### 4.3 真值与信息流

- 世界真值可以用于生成模拟测量、推动物理、判定伤害和计算评估结果。
- 模拟测量必须经过视野/可见性、噪声、延迟及丢失模型，再进入现有 PnP 和预测器；从这里产生策略可用状态。
- Actor 和动作掩码不得读取仿真真实目标状态、真实命中结果、未来帧、种子或人为实验倒计时。
- 当前 self_referee 的底层结构也含 actual_shots、damage_dealt、damaging_hits、kills 等评估计数。名称带 self 不代表整包都属于策略观测，必须显式建立白名单。
- 奖励、事件真值和诊断可以放入独立的训练/评估信息，不能被观测拼接或归一化过程意外吸收。
- 短历史在回合、目标重建及策略切换时按统一协议处理；具体填充、复位条件和窗口长度列入待定稿表。

## 5. 动作表与执行语义

### 5.1 九个动作

下表用语义名称表示九个动作；整数编号暂不冻结，最终编码应与模型版本一起保存。

| 语义动作 | 槽位选择 | 单发请求 | 行为 |
| --- | --- | --- | --- |
| WAIT | 不提交新选择 | 否 | 继续原有效槽位的弹道与 MPC 跟踪；没有有效槽位时停止目标跟踪。 |
| TRACK_SLOT_0 | 0 | 否 | 当周期采用槽位 0。 |
| FIRE_SLOT_0 | 0 | 是 | 当周期采用槽位 0，并请求一发。 |
| TRACK_SLOT_1 | 1 | 否 | 当周期采用槽位 1。 |
| FIRE_SLOT_1 | 1 | 是 | 当周期采用槽位 1，并请求一发。 |
| TRACK_SLOT_2 | 2 | 否 | 当周期采用槽位 2。 |
| FIRE_SLOT_2 | 2 | 是 | 当周期采用槽位 2，并请求一发。 |
| TRACK_SLOT_3 | 3 | 否 | 当周期采用槽位 3。 |
| FIRE_SLOT_3 | 3 | 是 | 当周期采用槽位 3，并请求一发。 |

### 5.2 执行约束

- 单发请求不等于实际出膛。命令生成、传输/消费、供弹、出膛和命中需要可关联且互不混淆。
- 不满足条件时拒绝当前请求，不因为条件稍后变好而补射。固有的命令和供弹延迟继续存在。
- Talos 目前通过 fire_advice 上升沿触发单发；适配器需要将策略请求转成正确的脉冲语义，连续高电平不能误当成连续新请求。
- RL 新选槽位当周期生效，不经过旧换板确认时间；依然执行弹道和受约束 MPC，不会瞬间改变云台姿态。
- 换板当周期允许请求射击，实际发射取决于出膛时的真实枪口状态。
- 允许预测性预瞄，旧 60°/70°门限不作为 RL 候选屏蔽条件。WAIT 的“原槽位有效”也不能暗中复用旧离开角门限。
- 原有瞄准窗口、稳定周期和不确定度经验门限留在 RulePolicy；RL 使用这些量作为特征和诊断。
- 公共层继续检查输入有效性、外部使能、求解结果、机械及裁判约束；TEMP_LOST 期间首版禁止射击。
- 动作掩码是决策时的可执行性估计，不是实际执行确认；最终 MPC 求解、反馈变化或发射机构都可能导致拒绝。不得为减少拒绝而向掩码泄露环境真值。
- 输入失效时不能借助规则回退绕过原有故障处理。

### 5.3 只学习开火的隔离要求

规则策略必须独立且完整地决定实际槽位，RL 只决定该槽位上的单发请求。不能因 RL 选择 WAIT 而保留上一槽位、推迟规则换板。

若对照实验复用九动作空间，可在规则槽位有效时仅开放该槽位的 TRACK/FIRE 对，使用 TRACK 表达不射击；无有效槽位时只开放 WAIT。最终绑定方式需在动作编码定稿时确认，并通过“任意开火策略不改变规则选板序列”的回归检查。

## 6. 时间、奖励与回合

### 6.1 时间与复位

- 训练由显式仿真时间驱动，每次策略决策间隔 10 ms；物理、云台积分、测量采样和裁判采样各自保持明确频率与更新顺序。
- 训练时钟不能与 wall clock、epoch 纳秒或 C++ steady_clock 直接混用；适配关系需文档化。
- 阶段 2 需验证暂停、同步步进、倍速推进、多实例隔离及重置。
- 复位至少覆盖机器人状态、在途弹丸、待执行命令、战斗统计、预测器、MPC、反馈估计、射击脉冲和策略历史。
- RL 异常停用锁存与普通回合复位分开；不能通过自动重置回合绕过 D34 的手动重新启用要求。

### 6.2 训练奖励与时间截断

基础奖励为每个状态转移期间本方弹丸造成的实际伤害增量，不奖励“请求已提交”“瞄准误差减小”或“碰到车体但没有伤害”。

耗弹、换板和无效请求先作为指标。以后若加入惩罚或过程奖励，应记录新的奖励版本，并与伤害唯一奖励做独立消融。奖励归一化及折扣时间尺度尚待确定，不把未经测量的权重当作用户已批准数值。

训练按持续任务处理：

- 人为时间限制属于 truncated，不自动等同真实任务终止 terminated。
- 保留正确的截断前/终止前观测，正确处理价值自举和向量环境自动复位。
- 不向网络暴露人为实验倒计时。
- 评估末尾的强制停火与弹丸结算不是普通训练状态，不直接复制为训练轨迹尾段。
- 在途弹丸的收益不能同时计入显式尾部奖励和同一边界的价值自举。具体 rollout/截断实现列入待验证事项。
- 不假设“30 秒评估窗口”已经确定了所有训练回合长度。

### 6.3 标准靶评估生命周期

1. 使用相同场景、资源条件和禁发预热流程；预热不允许消耗弹量或热量。
2. 达到统一确认跟踪条件后开始正式计时，正式窗口仍可发生丢失与恢复。预热超时条件、初始控制状态及历史初始化需统一定稿。
3. 标准靶使用足够高的血量以避免提前结束，正式发射窗口为 30 s。
4. 窗口结束后停止新射击，目标按原脚本继续运动。
5. 只结算窗口内实际出膛的弹丸，直到它们全部消失或达到生命周期上限。窗口后出膛、旧回合弹丸及重复事件不计入本窗口成绩。
6. 尾部不增加新的发射时间预算。记录请求、实际出膛和命中的时刻，不能按“请求发生在窗口内”替代“实际出膛在窗口内”。
7. 窗口边界等号规则、迟到命令处理和事件封账顺序在协议定稿时明确，并对所有策略一致。

真实血量测试另行统计首次命中与击毁时间；未命中、未击毁及超时结果必须单独报告，不能只统计成功回合。

## 8. 对照、指标与验收

### 8.1 对照组与公平性

- B0：当前固定规则配置。
- B1：有限调参后的规则配置，只调整选板与开火参数。
- L0：规则完全负责选板，RL 只决定是否请求单发。
- L1：RL 联合选板与开火，最终通用部署策略。

规则调参只使用训练/验证场景。弹道、MPC、公共执行约束、场景条件、资源预算和计分口径共用。规则拆分等价检查与加入新公共适配后的效果比较应分别记录，不能把接口变更产生的收益归因给 RL。

保存代码版本、工作树差异、运行配置、种子、观测/动作/奖励版本及模型文件信息。当前配置快照不代替正式实验前的完整版本冻结。

### 8.2 指标口径

| 指标 | 用途与边界 |
| --- | --- |
| 固定窗口有效伤害 | 主指标；使用相同 30 s 发射预算及尾部结算规则。不得以纯接触次数代替实际伤害。 |
| 命中率、实际出膛数 | 分析射击效率；是否以装甲接触或造成伤害作为命中、重复接触去重等定义需要冻结。零出膛不能默认为 100% 命中。 |
| 单位伤害耗弹 | 分析资源效率；零伤害结果单列，不能通过除零处理隐藏失败回合。 |
| 首次命中、击毁时间 | 响应能力；计时起点与超时/未成功统计一致。 |
| 热量锁定、拒绝请求 | 观察资源与执行行为，区分本地请求、传输成功和实际发射。 |
| 换板频率、云台抖动 | 观察稳定性；具体计算方式及统计窗口待冻结。 |
| 控制耗时、P99、超期次数 | 验证 NUC 可部署性；同时测量策略部分和完整控制链，平均值不能替代尾延迟。 |

首版研究完成与推荐替换分开：

- **研究完成**：训练、部署和评估闭环完整，实验结论可复现；暂未超过传统火控也可交付可信结论。
- **推荐替换**：相对较强传统基线，整体伤害提升得到统计支持，各主要场景类平均伤害退化不超过 5%。
- 较强基线的选择流程、主要场景类划分、汇总权重、统计检验、零基线伤害处理及样本量需在最终测试前冻结，不能事后选择最有利口径。
- 影子模式用于特征、决策和时延检查，不提供真实执行的反事实收益，不能作为伤害提升证据。

## 9. 训练平台、部署和异常处理

- DGX Spark 是首个远端训练平台；ARM64 控制库、Python 绑定和依赖兼容性提前纳入工作。尚未在 Spark 上构建或验证。
- 优先在训练机器上同时运行环境与训练器；NUC 负责本地接口验证和最终完整视觉闭环。
- 正式预算尚未决定：先测采样吞吐和小规模学习曲线，再确定步数、种子数和时间预算。
- 模型导出和部署应同时保存观测顺序、坐标/单位、归一化、动作映射、历史与掩码版本。
- ONNX 导出与 OpenVINO CPU 推理是此前提出的候选实现路线；具体依赖版本、算子兼容性和性能仍待验证，不列为已经完成的部署。
- 此前建议的策略特征构建加推理 P99 小于 1 ms 是待验证的性能预算建议，不是用户 35 项决策中的实测结果，也不等于完整控制截止时间。
- RL 输出非法、版本不匹配或错过控制截止时间时，丢弃该决策，当周期不提交新的射击请求。输入仍有效时由规则策略接管，RL 保持停用直到手动重新启用。
- 超时结果丢弃不能被误写成“已经实现可抢占推理”；推理阻塞、截止时间和现有执行器超时之间的保障方式需在部署设计中验证。
- 原有输入过期、通信故障等处理继续生效；规则回退不得绕过这些条件。
- 实机命令、反馈与裁判接口属于下一里程碑，NUC 仿真推理完成不等于实机验收完成。
