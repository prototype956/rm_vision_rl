## 模块与调用顺序

视觉主项目是共享实现的唯一生产源码位置。`RulePolicy` 保存原有槽位滞回、确认时间、开火误差窗口、稳定计数和不确定度判断；`FireControl` 保存弹道、MPC 和单发脉冲调度；`ControlSession` 保存反馈估计、已发布命令匹配、姿态投影和有限轨迹回退。

规则顺序保持为：选择槽位 → 构造弹道与 MPC 轨迹 → 规则开火判断 → 公共约束 → 命令发布。

`ControlRuntime` 只负责固定周期线程、输入快照、通信、时钟采集、监督器和诊断发布。其调用方式为：

```cpp
auto result = session.Step(input, actuator, sink_healthy, now, command_timestamp_ns);
const bool sent = sink.Send(result.output.command);
session.AcknowledgePublication(result, sent, now);
```

每个会话由单一调用序列拥有。`Step` 与 `AcknowledgePublication` 交替；重复确认、其他会话的确认及过期确认被拒绝。会话不可复制或移动。确认标识仅在当前进程有效，不是传输协议或策略特征。

`Step` 可额外接收 `PolicyDecision`，用于阶段一脚本策略和后续外部策略。规则分支没有重复求解四份 MPC；外部观测构造按四槽位计算弹道候选，最终只对选中槽位构造完整轨迹。

续作补齐 `StepWithPolicy(..., ControlPolicy)`：会话在融合反馈和投影位姿后，火控完成
回合/目标/模式复位及输入校验，再构造 `PolicyObservation` 并调用一次策略。策略和 MPC
使用同一快照；无效输入直接停止，不调用策略。回调不得保存引用或重入会话，异常向调用者
传播并取消本地脉冲。策略自有历史由后续策略实现管理，模型故障锁存仍属于部署阶段。
确认时间不得早于当前 Step；通信时间戳重复或回拨时命令历史仍有容量上限。

## 公共数据契约

### PolicyObservation

这是未归一化的语义对象。包含正式 `ArmorPredictionOutput`、融合云台反馈、自身裁判白名单、同帧底盘观测、四个 `BallisticSolution`、九位动作掩码、三类数据年龄、上次槽位与距本地脉冲请求的时间。`VERSION=1`。

位置采用视觉项目 world Z-up 坐标；变换名称表达 child 到 parent；距离单位 m，角度 rad，年龄/飞行时间 s，导数采用对应秒制单位。装甲尺寸、半径、姿态和不确定度取自正式估计输出。

时间戳、回合、序号和目标代次是对齐及复位元数据，后续张量转换不得将它们当作绝对时间或回合特征。观测没有仿真伤害、命中、击毁、出膛计数、未来帧或实验倒计时。固定短历史、张量排列、归一化和缺失值编码在后续冻结，本阶段没有伪造这些结果。

掩码使用数据有效性、估计弹道可解性、跟踪状态、本地脉冲/间隔和公开裁判信息。掩码不使用旧 60°/70°角度门限、瞄准窗口、稳定次数或不确定度经验阈值。最终 MPC、通信和仿真执行仍可能拒绝一个决策时可选的动作。

### PolicyDecision

| 编码 | 行为 |
|---|---|
| 0 | WAIT：不换板、不创建新射击请求；原槽位有效时继续跟踪。 |
| 1、3、5、7 | 分别跟踪槽位 0、1、2、3。 |
| 2、4、6、8 | 分别跟踪槽位 0、1、2、3，并请求一发。 |

外部模式立即换板，允许同周期请求射击；实际云台仍受 MPC 约束。没有有效槽位则停止目标跟踪。非法整数动作拒绝执行。

`FireOnlyPolicyAdapter` 每周期独立运行规则选板；不射击也返回规则选定槽位的跟踪动作。掩码只开放该槽位的跟踪/单发动作；无槽位才开放 WAIT。它不能通过等待保留旧槽位。

### ControlStepResult

复用原正式控制输出及独立诊断，增加本地 `shot_requested`、`shot_accepted`、会话确认标识和外部决策记录。区分本地请求、脉冲接受、发布成功和实际出膛。前两者及发布状态均不表示弹丸已经发射。

规则脉冲保留既有宽度、重复间隔和取消条件。外部 WAIT/纯跟踪可以维持已接受脉冲直到结束，但不创建新请求。脉冲忙或间隔不足时拒绝新请求，不排队补射。公共禁发、求解失败和发布失败取消本地脉冲；已经传输或进入发射机构的请求不被假定为可撤回。

## 裁判、时间和复位

裁判适配器仅白名单提取自身存活/禁发状态、热量/上限/冷却速率、有限或无限弹量模式和剩余额度。对未知枚举、无效值、未来采样或回合不匹配标为无效。

采样年龄 = 同帧仿真时刻减裁判采样时刻 + 该帧至当前接收时刻的单调经过时间；后续再加接收后的单调时间。不同来源的时钟纪元不直接相减。`timing.max_referee_age_s=0.30` 为可配置工程默认值；旧 YAML 未提供该键时采用同一默认值。该参数不是实测结果。

所有控制状态计时由调用方传入，时间零点合法。同一回合的会话步进时间必须递增。系统时钟仅由运行时提供通信时间戳；求解耗时测量只参与诊断。

| 事件 | 处理 |
|---|---|
| 新回合 | 重建火控/求解器，清空反馈、命令历史、脉冲、回退轨迹和计时；允许新时间原点。 |
| 成功初始化新目标 | 预测器递增 `track_generation`；清理槽位、瞄准稳定性和旧目标轨迹，保留己方反馈及机械间隔。 |
| TEMP_LOST 恢复 | 不增加目标代次；有限时间继续控制，禁止射击。 |
| 控制模式或通信变化 | 保留既有清理命令投影、停止/回退和监督器行为。 |
| MPC 失败 | 仅在原有条件满足时使用已成功发布的同槽位轨迹，最长 100 ms，始终禁发；过期停止。 |

正常 LOST 状态没有有效目标几何，不被误报为数值异常。可控制状态下的非有限几何、未来反馈等在外推前拒绝。

## 构建和验证

独立构建：

```bash
cmake -S /home/nuc/Workspace/rm_vision_2027 -B /home/nuc/Workspace/rm_vision_rl/artifacts/build-control-core \
  -DBUILD_CONTROL_CORE_ONLY=ON -DBUILD_MAIN=OFF -DUSE_OPENVINO=OFF -DUSE_MINDVISION_SDK=OFF \
  -DCMAKE_BUILD_TYPE=Release
cmake --build /home/nuc/Workspace/rm_vision_rl/artifacts/build-control-core --parallel 4
```

依赖 Eigen、OpenCV core、yaml-cpp、fmt、spdlog、Threads，以及原预测运动模型使用的 Ceres Jet 头文件。无需检测器、相机 SDK、Talos 通信、Foxglove 或窗口组件。共享静态库启用 PIC。完整 PnP/EKF 的无渲染入口留到阶段二。

验收程序：`mv-control-reference`、`mv-control-session-reference`、`mv-control-acceptance`；参数均为视觉项目的 `src/config/modules` 目录。差分规则：整数/布尔状态精确比较，浮点绝对容差 1e-9、相对容差 1e-7；耗时和外部时间戳不参与等价比较。

独立与完整构建的这三个控制验收程序均位于构建目录的 `test/control/`；主程序位于 `bin/`。
可复用差分命令和基线适配来源见 [验收工具说明](../tools/phase1/README.md)。

Foxglove `/vision/control/state` 新增本地请求/接受字段，以及 `runtime.control_compute_time_us`、`runtime.referee_age_s`。计算耗时包括同步会话、输入复制和发布结果处理，排除通信 Send 用时；记录分位数、最大值及计算耗时超过 10 ms 的比例，不能把线程唤醒抖动与计算超时混为一谈。

验收矩阵和实际结果见配套记录。没有训练模型；这些验证不证明 RL 伤害收益，也不证明 ARM64 或实机部署已完成。
